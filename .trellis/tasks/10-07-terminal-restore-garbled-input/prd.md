# 修复终端恢复乱码与异常自动输入

## 用户问题

应用关闭后重新打开并恢复终端，终端出现乱码，并持续出现非用户主动输入的字符。用户同意创建独立修复任务。尚未获得异常字符样本，不将控制序列响应回流假说认定为已确认根因。

## 目标

- 定位乱码及异常输入的实际生产边界，说明两种表现是否为同一原因。
- 恢复回放不应被误转发为对当前 PTY 的用户输入或重复命令。
- 正常键盘、粘贴、IME、交互程序实时终端查询响应与 CLI resume 必须保持兼容。
- daemon attach / 重连 replay 与快照重建恢复保持身份、路径和原有时序。

## 调研与安全约束

- 当前仅获任务创建授权，先只读定位并提出设计 / 执行方案，批准后实施。
- 不删除或清空用户快照、配置、会话，不对真实终端自动输入测试命令或复现字符。
- 不用全局关闭 onData、丢弃所有控制序列、固定延时或输出文本猜测等方式隐藏症状。
- 先过根因分诊，产出根因陈述、发现清单和场景矩阵；GitNexus 不可用时按领域契约与符号检索降级，不把未知图风险当成低风险。
- 保留此前标签栏及 Worktree 状态修复，不提交或同步 Git。
- 用户可见文案如有改动需 zh-CN / en-US；交付记录暂用 TEMP，同步 CHANGELOG.md 与 docs/功能清单.md。

## 必须覆盖的场景

- daemon 已存在 attach、断线重连 replay、daemon 不存在的 shell 快照回放与 CLI resume。
- 普通 PowerShell / CMD / Pwsh / Bash、WSL、SSH；Claude / Codex 等交互 CLI。
- 主目录与 Worktree；可见与隐藏后重开；单终端与深层 / 混合分屏；切换活动终端和挂载中断。
- 本窗口聚焦 / 失焦、最小化 / 托盘、恢复 ask / auto；hook 有 / 无不应影响恢复输入安全。
- Unicode / 中文、多字节分块、ANSI / OSC / DSR 等控制序列、历史尺寸变化与 live 输出交错。
- 真实用户恢复期间输入、恢复完成后输入、IME / 粘贴、实时查询响应不能被错误阻断。

## 验收

- 以可确定复现 / 控制序列样本 / 实际调用证据证明根因，不仅在症状处兜底。
- 历史回放不产生重复向 PTY 的写入或后台自动输入，乱码来源得到修正或明确证据解释。
- live 输入与真实交互程序查询响应保持；恢复中断 / 清理后无持续抑制、监听重复或响应循环。
- 对改变行为做最小定向自动测试，必要跨层检查和独立严格架构检查；手动未执行的恢复场景如实报告。

## 初步线索（非根因结论）

useTerminalInput 的 terminal.onData 与 onBinary 会写入 PTY；xterm 的数据事件可能也包含终端控制序列查询的自动响应。需要追踪历史输出是否与实时输出区分、回放异步写完成范围，以及查询响应 / Unicode 解码是否安全。
