## Actual usage

Use the existing **System resources** toolbar/side-panel entry. The existing panel now contains **System** (default on mount) and **Terminals** tabs, in both merged and independent side-panel compositions. Select Terminals to see this window's runtime original PTY sessions, including hidden terminals and ephemeral Pi sessions. Current-work references never add another row. Metadata-only editor/history/subagent transcript rows and remote-owned handoff rows are excluded.

Each row shows existing title, resolved project/worktree (or missing/unbound context), original session ID, known runtime/SSH state and existing hook state when present, hidden state, working-set value, complete/partial/unavailable status, observed/enumerated counts and localized reasons. The panel shows 24-hour sample time, page/total count, previous/next controls and explicit refresh. It samples up to 64 original IDs per page. Page membership is stable ID order before sorting: descending valid observed memory within the current page only, unknown last, session ID ties. Copy explicitly says this is not a global ranking.

The label is **Observed working-set sum**, including Pi/descendants in the owning Job. Shared pages can be counted repeatedly; it is neither private memory nor unique physical RAM. No all-terminal total or allocation of app/WebView/GPU/daemon RAM. Null/unsampled observations remain an em dash/unknown, never fabricated zero. SSH/WSL and unsupported/old daemon/owner failures have safe bilingual explanations. There are no process kill/pause/restart/restore/create controls and no command-line/environment display.

Click a row title to navigate to the existing source ID. Existing current-work members activate there; nonmembers leave current-work view before source selection. Source store `setActive` unhides, selects the correct workspan/deep pane and clears incompatible source fullscreen. The extracted listener also clears incompatible current-work fullscreen for member targets. Deleted IDs are rechecked against the live store and ignored. No current-work membership insertion and no process creation/restoration occurs.

## Structure / race protection

- `api/terminalResources.ts`: actual `terminal_resources_get_snapshot({ sessionIds })` invoke, input pre-dedup bounds, typed DTO, decimal precision strings, response identity/shape/null validation and privacy allowlist copying. Only fixed native errors become UI messages. No daemon connect, spawn or upgrade call.
- `lib/terminalResourcePolling.ts`: 2500ms scheduler, generations and module-lifetime unresolved-request gate. Hide/unmount/page/session/identity changes invalidate late success AND error without clearing the outstanding request. A newly active view waits for settlement, then wakes; no overlapping native requests across panel remounts.
- `hooks/useTerminalResources.ts`: open/visible/active gate supplied by composition, document visibility gate, synchronous visibility/disconnect invalidation and layout-effect lifecycle. Renderer transport disconnect generation plus original session incarnation/status key invalidates UI observations. Native command independently revalidates bridge/client generation and daemon owner revision before any successful return; no owner tokens enter UI identity keys.
- `components/TerminalResourcesPanel.tsx`: complete functional panel rather than skeleton. Uses existing terminal/project/worktree stores and existing hook statuses. System collector is disabled while Terminals is active.
- `hooks/useTerminalNavigationListeners.ts`: cohesive extraction of existing current-work target/action listeners plus a separate resource inspection target listener. Existing add-capable current-work target semantics are preserved, never reused for inspection nonmembers. Controller remains 1967 physical lines, without compression or exceptions.
- `terminal.en-US.ts` / `terminal.zh-CN.ts`: matching new labels, reasons, explanations and aria copy.
