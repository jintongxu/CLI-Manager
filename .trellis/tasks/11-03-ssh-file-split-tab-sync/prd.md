# 需求规格：当前工作模式下 SSH 远程文件编辑分屏与标签自愈联动

## 1. 业务背景与痛点
- 在「当前工作」（Current Work）工作流中，开发者在 SSH 远程终端中排查问题时，经常需要从左侧 SSH 文件面板打开远程代码或配置文件进行编辑。
- 痛点：
  1. 当前双击远程文件后，文件编辑器会直接替换当前激活的终端叶子窗口，导致正在运行的 SSH 终端被顶掉，无法同屏边看日志边改文件。
  2. 顶栏标签页只显示泛化的“文件”标题，无法一眼看出打开的具体是哪个远程文件、是否包含未保存的修改（`*` 脏标记），也没有标明所属的远程主机上下文。
  3. 当在编辑器里关闭所有打开的文件后，空的编辑器面板依然留在分屏区域中，不会自动关闭，需要手动关面板切回终端。

## 2. 交互与行为规格
1. **自动右侧分屏（Split Right）**：
   - 在「当前工作」模式下，当触发打开的文件来自 **SSH 远程环境**时，系统应判断当前激活窗口是否包含 SSH 终端；若是，自动在右侧创建分屏放置该文件编辑器，形成「左侧终端 + 右侧代码」的经典对照布局。
2. **顶栏标签动态自愈展示**：
   - 标签图标：显示文件专有图标（`FileText`），区别于终端图标。
   - 标题：显示当前正在编辑的真实文件名；若文件有未保存内容，标题末尾动态添加 ` *` 脏标记。
   - 上下文标识：上下文辅助信息标明远程主机，例如 `SSH: <主机名>`。
3. **文件全关自愈清理**：
   - 当用户通过标签关闭按钮、批量关闭，或在弹窗确认保存/放弃修改后，若该文件编辑器内已**无任何打开的文件**（且无 Diff 标签），应自动销毁该编辑器面板，将分屏空间和焦点归还给对应的 SSH 终端。

## 3. 验收标准
- 在「当前工作」中打开 SSH 远程文件，稳定分在 SSH 终端右侧，不遮挡、不替换终端。
- 编辑修改时顶栏标签实时出现 ` *`，保存后消失；能清晰辨识所属远程主机。
- 逐个关闭文件，关到最后一个时，右侧编辑器面板自动关闭，光标与焦点平滑切回左侧终端。
- 本地文件项目不产生负面回退，保持既有行为。
- `npx tsc --noEmit` 与 `npm run check:architecture` 0 报错。
