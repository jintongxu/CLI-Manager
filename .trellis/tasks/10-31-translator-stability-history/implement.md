- Native storage is the authority: history recording is NOT a Settings/Zustand preference and cannot be changed by sync. Main/translator-only commands: `translator_history_get_recording`, `translator_history_set_recording({enabled})`, `translator_history_list({search,cursor,limit})`, `translator_history_delete({id})`, `translator_history_clear()`. Missing tables return `translator_history_unavailable`, no runtime DDL or second migrator.
- At latest successful text/image completion: acquire SQLite `BEGIN IMMEDIATE` writer asynchronously before opening authority mutex, then blocking worker revalidates generation/attempt, inserts text-only accepted DTO and commits while holding authority. Close/invalidate linearizes before validation (no write) or after accepted commit. Toggle/delete/clear serialize through SQLite writer. No opening mutex while waiting for another DB writer. Native close callback no longer silently skips invalidation on try_lock contention. Screenshot publication rechecks opening/accepted identity after persistence and cannot resurrect old UI.
- UUID successAttemptId and timestamp are native-produced once per success; receipt and row insert share transaction. Repeated delivery/duplicate accepted attempt cannot insert twice; receipts persist through delete/clear/reopen so old success cannot resurrect deleted content. Receipts contain only random ID (no translation text). Turning recording OFF keeps old rows and only stops subsequent accepted commits. No images, screenshot paths, endpoint/config/secret fields in storage DTO/schema. User-entered/translated text is intentionally retained when enabled; this is not a content-redaction feature.
- Storage errors preserve translation success and carry **saveWarning: `translator_history_save_failed`**; no model retry or error-card conversion. Text accepted DTO + Zustand saveWarning and screenshot result payload carry this warning. UI rendering is Todo32, not this lane.
