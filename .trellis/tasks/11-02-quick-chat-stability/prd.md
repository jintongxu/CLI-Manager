# 快聊稳定性、内存与退出清理（下一版）

## 目标
把全局快聊从“能用”推进到“可靠长期运行”：收敛会话生命周期、按原因分级错误、完善历史搜索，并消除已核实的内存增长点、补齐退出清理。

## 已确认（批准计划 13210bab47cd7b06d0ee3468b44570e6bafa514f6af9efc5dc0b86082b268b56）
用户明确要求：生命周期稳定化 + 错误提示改进 + 搜索完善，并**防止内存泄漏**、**优化退出清理**。版本记录使用 TEMP。

## 已核实缺陷
1. `CommandLedger.results` 保留每个命令 ID 的 Promise，上限 10 万条且永不淘汰。
2. `ChatController.deleted` / `deleting` 只增不减。
3. Rust `runtime.seen` 仅在 reserve/cancel 按 600 秒清理，达 4096 后直接 `chat_capacity`；`unsaved` 无上限。
4. 退出不释放快聊 `MAIN_CHANNEL` / `REMOTE_CHANNEL`、不注销全局快捷键，前端 publish 定时器无退出清理。
5. 快聊空选中可能触发面板隐式 `create`；错误统一显示“重试”，不区分原因。

## 需求与验收
- 快聊当前会话只由 owner 持有；任意时刻最多一次补建；Workspace 只选择不重复创建。
- 生成中删除、批量删除含当前项、隐藏后删除、放大后删除、重连恢复、owner epoch 切换均有确定结果，不停留旧 ID。
- 错误按原因分级（未就绪、会话不存在、存储失败、协议不支持、超时、容量上限）并给出对应动作，中英文同步。
- 历史搜索防抖、显示搜索中与匹配数量、可清空，保持“后端匹配分页 + 来源 Tab 客户端过滤”的真实语义。
- 所有长期容器有明确上界与淘汰策略；去重失败时 fail-closed，不静默重放。
- 退出先 drain 再释放通道与快捷键，不截断最后一次快照；不新增第二条退出权威。

## 非目标
不改历史迁移字节、不放宽 chat main-only 授权、不动 PTY/WSL/Worktree/CLI Hook、不新增依赖、不重置数据库。

## 人工验收（本轮不执行，需明确报告）
真实内存曲线、进程退出后的资源释放、后台/托盘唤起、多屏 DPI、中英文切换、真实供应商调用。
