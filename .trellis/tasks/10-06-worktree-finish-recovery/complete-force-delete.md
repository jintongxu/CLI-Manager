## Todo14 implementation — authoritative replacement IPC contract

This appendix supersedes prior `branchPreserved` / branch-preserving force contracts, not their historical verification evidence. Normal finish/merge/discard behavior and finish receipts are unchanged.

- `git_worktree_force_delete_inspect({ req: FinishRequest })` returns `{ token: string, confirmedPath: string, deleteBranch: true, branchOid: string | null, pathMissing: boolean }`. `confirmedPath` is the exact original record spelling. `deleteBranch: true` means the matching **local** `refs/heads/<wt branch>` is always part of this operation, with no switch; `branchOid` is the inspected direct reference tip, or explicit `null` if absent. Symbolic branch refs are rejected. All existing request/native identities/full porcelain/root-missing bindings remain; the authorization now also binds this optional OID.
- `git_worktree_force_delete_validate({ req, token, confirmedPath })` returns the same inspection contract and original token after read-only revalidation. It does not refresh issue time or consume a successful authorization. Original token validation precedes any frontend session close/release; changed OID (including missing→present), other-worktree use (including physical main), expired token, request/path/root/registration changes fail closed. Frontend also compares returned `branchOid`, `deleteBranch`, `pathMissing`, token and exact path with original confirmation before session effects.
- `git_worktree_force_delete({ req, token, confirmedPath })` returns `{ done: true, branchDeleted: true }` **only** when the directory root, target Git registration and matching local branch are absent. `branchDeleted: true` means the absence postcondition is satisfied, including an already-missing branch; it is not a claim that a deletion occurred in this call, that SQL completed, or that anything was merged. Missing branch names are not accepted: request branch must remain a valid non-base `wt/<task>` name even when its ref is missing.
- Execute consumes the original token, repeats full binding checks, safely unlinks the directory, verifies root absence, performs the existing target-scoped dry-run/prune checks, verifies no target registration remains, then rechecks branch use/current OID. A present ref must equal the captured OID. Deletion uses `git update-ref --no-deref -d refs/heads/<branch> <capturedOID>` (atomic expected-old-OID comparison; no add/commit/merge/push or remote operations). Missing ref is idempotent. A new/advanced/recreated tip differing from the original binding is never authorized by old confirmation; branch absent→recreated is rejected, including after directory deletion. Final ref absence and no other-worktree use are checked before returning done. Force-local path comparison strips Windows extended prefixes on both sides, including paths missing but still present in Git porcelain; shared normal-finish path helpers were not changed.
- Branch deletion errors after filesystem/prune success return errors, consume authorization, and prevent SQL/local/sidebar removal. The existing failed-force UI offers only **fresh inspection + precise typed-path confirmation**; this works with missing directory and a remaining branch. SQL failure after full backend success leaves the record; fresh missing-path/missing-branch confirmation finalizes force cleanup without merged inference or finish ack. Refresh failure after SQL/local removal only warns, never redoes Git. Confirmation shows actual null-OID missing-branch state and zh/en warn about uncommitted/untracked loss **and unmerged commits losing the local branch reference**, no remote deletion, push, or rollback of prior merges.
