# 终端应急与重建

批准方案：436969945c6a6abcb6670114920ea27aff20a3659d5a41c60f3c6ed1856ddb4b。

- 应急 Shell：保留原终端，相同目录、Shell、环境变量及 WSL 发行版另开干净 Shell，不启动/恢复 CLI；当前工作模式下正常加入并激活。
- 重建：先创建候选及订阅，再严格关闭旧 PTY，同步原位替换目标 ID；保持其它终端、布局节点/比例/顺序、当前工作成员和用户并发编辑。
- 候选准备失败不关闭源；源关闭拒绝则清理候选，清理失败仍保有明确资源所有权。
- 持久化失败与进程失败区分，不能重试已提交的创建。
- 同一源实例恢复操作去重，协调普通关闭与强制结束；用户主动关闭后不得复活标签。
- 路径解析覆盖继承项目、有效且关联正确的 Worktree、本地和非默认 WSL；SSH 及非 PTY 保持禁用，项目配置改变后再次验证。
- 入口风险分组、处理中禁用、详细确认与分类错误；中英同步，键盘可达。
- 不做 SSH 恢复、CLI 重放、独立恢复中心；不自动提交合并推送。

## 验收

定向故障注入覆盖创建/订阅/严格关闭/候选清理/保存失败、重复点击、关闭竞态、并发布局、多 Workspan、当前工作、WSL 发行版、丢失 Worktree、源/解析后 SSH。运行 TypeScript 与 strict 架构检查。实机不可测范围明确列出，不宣称通过。
