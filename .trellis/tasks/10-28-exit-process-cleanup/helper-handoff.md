# App-local helper implementation handoff

## Callable integration contract
All functions are synchronous: invoke on coordinator blocking worker, never UI thread. Pass the SAME monotonic Instant deadline through the attempt. Ok evidence is returned only after observed termination; Err retains unfinished registered slots. Error codes include helper_timeout/helper_lock_poisoned/helper_exit_fenced and checked Job API errors. Coordinator maps these into typed receipt resources; APIs do not mint transaction receipts.

- `commands::cc_connect::CcConnectManager::{prepare_exit(deadline)->Result<(),String>, stop_for_exit(deadline)->Result<&'static str,String>, resume_after_exit()}`. Stop verifies service/auth root signals, Job active zero, and retained stdout/stderr readers finished+joined; evidence summary `job_empty`. Profile, credentials and config are not touched by exit.
- `live_server::LiveServerManager` same methods/signatures; `worker_joined` means HTTP task completed (including aborted+awaited connection JoinSet) and watcher thread joined. Timeout retains servers and watcher handles. Normal stop also uses bounded stop rather than remove-first.
- `commands::web_server::{prepare_exit(&manager,deadline), stop_for_exit(&manager,deadline), resume_after_exit(&manager)}` same results. Existing worker-slot retention reused, `worker_joined`. No config/status/credential read in exit stop.
- `side_question::process::{prepare_exit(deadline), stop_for_exit(deadline), resume_after_exit()}` same signatures. IMPORTANT: `process` currently private in side_question.rs outside this task scope: integrator must re-export wrappers/make module crate-visible there. Registration remains active until root/tree and writer/reader cleanup proof; closing slots retain handles on deadline. Shutdown wrapper is now bounded, but native ExitRequested caller must be removed/replaced by coordinator to preserve minimize semantics (lib.rs intentionally not touched).

prepare fences before draining in-flight creation locks and never kills. Stop also fences defensively. Resume must be serialized after cleanup worker settles; retained slots still prevent replacement. Live prepare/start uses server registry mutex; cc uses operation mutex; web uses lifecycle mutex; side uses synchronous Registration admission. Existing admitted side workers are included through their registrations. Minimize integration must not call prepare/stop/shutdown.

## Implementation details and limits
- Shared bounded lock and owned child logic is in cc_connect/exit_process.rs (scope-local, no shared process_job edits). Windows launches suspended, assigns existing ChildJob before NtResumeProcess; failed admission/resume roots retained in failed registry for reap retry. Existing process_job dirty work preserved.
- Unix establishes process group before exec and issues one group SIGKILL before reaping; retry never re-signals possibly recycled PGID. Unix runtime NOT tested. Deliberately setsid-detached descendants cannot be proven by process-group absence; coordinator should not treat Unix helper tree proof as the full Windows Job guarantee without further platform work. Unix summary is `process_signaled`, Windows summary `job_empty`; exact wire typed result remains coordinator responsibility. If ordinary protocol/status polling already reaped the Unix leader before stop, returns `helper_group_identity_unavailable` rather than signaling an unverified/recycled group; that slot stays blocked. Thus Unix full exit acceptance is not complete.
- Short-lived cc detection/config formatter subprocesses still use existing bounded shell_resolver helpers while holding operation admission. This change manages long-lived service/auth and side-question trees, not a wholesale shell resolver replacement.
- cc service now registers immediately after spawn instead of an unregistered 350ms startup inspection; normal refresh only removes slots after root/job/readers all finish. Early exit is observed later by refresh. Auth status verifies tree stop before consuming result. Exit does not invoke credential parsing.
- Deadline holds a per-resource mutex while polling, not an application-global mutex. Concurrent callers use timed try_lock. Ordinary non-exit status/start APIs still use existing blocking mutexes; coordinator admission must keep them out during cleanup.
- Final Drop paths outside explicit exit still have baseline behavior (live watcher Drop joins). Verified stop removes watcher only after joined. Do not rely on Drop as exit completion proof.
- Both report schema paths (.pi/agents/general-executor-report.schema.json, flow/agents/general-executor-report.schema.json) absent; inline executor schema used.
